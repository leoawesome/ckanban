# helper

The helper: the side call that decides when and how to tell the user something waits on them, and the channels it uses. The runner (`runner.ts`, class `HelperRunner`; constants and types in `runner-config.ts`, text helpers in `runner-text.ts`, all re-exported from `runner.ts`) wakes the helper, checks its decision (`decide.ts`) and carries it out through the core (`core.ts`).
Also here: waits and snoozes (`waits.ts`, `attention.ts`), messages and summaries (`messages.ts`, `summary.ts`, `line.ts`), settings and night hours (`settings.ts`), notifications (`notify.ts`, `channels.ts`, phone push `push.ts`, `webpush.ts`), and Telegram with its front desk (`telegram.ts`, `tg*.ts`, `frontdesk*.ts`).
Tests sit next to the code (`*.test.ts`); tests that boot the server are in `test/`.
With the Rust board on (satellite mode, `src/core/satellite.ts`), the runner, the watching of tickets and the helper's files are Rust's (`rust/board/src/helper/`, P1a): this daemon builds no `HelperRunner`, its `WaitStore` and `MessageStore` only read the files (again when they change), and its writes go to Rust through `HelperEdge` (`core.ts`, `src/core/satellite-edge.ts` `rustHelperEdge`): Telegram's taps, notify.json, the front desk's `seenInChatAt`, the Settings test message. It still sends to push, ntfy and the Mac banner (Rust asks `helper-send`) until P1b. Telegram and the front desk run in Rust since P1c (`rust/board/src/telegram/`): this daemon's notifier never polls the bot, plugs `noTelegramBoard` and leaves Telegram's files alone.
